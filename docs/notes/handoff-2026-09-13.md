## The honest gap: compiling is not running

found eleven miscompilations that no compile measure could see (context bounds
not merged into an implicit clause; primitive `if`/`match` arms not boxed;

types and on `getfield` receivers; type lambdas pickled as a parentless
`ALIASsym`; a value class's extension method pickled so badly that **scalac
crashed** reading our class files; …). All are fixed; the full list is in
`tests/BASELINE.md` under gate fifty-seven.

Both ledgers are now **empty**: `tests/cats_run.sh` is `progs=8 ok=8` and
`tests/gitbucket_run.sh` is `progs=6 ok=6`, and the gate's `new=0` rule keeps
them that way. Clearing the five entries took eight more roots, the sharpest
being that mixin forwarders were emitted for the whole linearization instead of
nsc's `mixinClasses` (the JVM refused the class for overriding a `final` trait
accessor), three pickle defects around type members (applied arguments dropped,
members minted per class file, refinement `type` declarations discarded — the
last one also caused cats' `OptionT` ambiguity), and a lambda over a
pattern-bound `for` losing its captured outer inside cats' own macro, which made
*scalac* throw while expanding.

Still open there, in `docs/notes/rh-cats-gitbucket-run.md`: `Database.forURL`

## Process rules that earned their place

* Compose, then run the **full workspace suite on the composed tree** before the
  gate: five cross-slice interactions were invisible to every slice's own suite.
* Assign each known root to exactly **one** slice and name the owners in the
  other briefs — three slices fixed `var x: T = _` independently.
* Let the slice that wrote the code **merge the integration branch itself** and
  reconcile duplicated rules; the coordinator merges serially.
* Hard roots: try an Opus slice first, escalate to Fable 5.1 only if it fails
  (the user's revised directive; Fable quota is limited).
* Don't start new slices while a gate runs — it doubles the gate's wall time.
* Java is Temurin 17 (`/usr/bin/java`); the Homebrew `openjdk@*` links are JDK 24
  and silently change the `names`/`numt` test data.
* A brief's cluster count is a hypothesis. This session it was wrong in both
  directions repeatedly: gitbucket's "29 backend errors caused by static
  members" were simply the first 29 errors of a backend that had never run, and
  "gitbucket is macro-bound" was a typer caching problem with macros costing
  0.9 s of 161.7 s.
