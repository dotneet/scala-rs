# Run-time differential probe: findings

`tests/rt_probe.sh` compiles every `tests/rtprobe/*.scala` program with
scala-rs (`--scala-library`) and with scalac 2.13.16, runs both under
`java -Xverify:all` (JDK 17, `/usr/bin/java`), and compares what they print.
It exists for the defects an error count cannot show: a program both compilers
accept but that behaves differently, or one only scalac rejects.

```
tests/rt_probe.sh                 # all programs, ~30 s warm (scalac results are cached)
tests/rt_probe.sh 'match_|neg_'   # a subset, by regex on the file name
SCALA_RS=path/to/scala-rs RTPROBE_DIR=/tmp/x tests/rt_probe.sh
```

Verdicts: `ok`, `MISCOMPILE` (both accept, output differs), `RUNTIME-ERR`
(scalac's run exits cleanly, ours does not), `WRONG-ACCEPT` (only scalac
rejects), `reject` (only scala-rs rejects), `bad-probe` (both reject a
program meant to compile). Programs named `neg_*` are meant to be rejected;
both rejecting is `ok`. Programs named `gap_*` isolate a construct scala-rs
rejects, so that the dense program it came from can run.

The dense programs cover initialization order, linearization and `super`,
overriding, default/named/by-name/varargs arguments, closures, nested
classes, pattern matching, interpolation, numerics and cooperative equality,
case classes, tuples, `Option`/`Either`/`Try`, exceptions and non-local
return, `lazy val`, implicits, value classes, specialization, arrays, `for`,
loops and `@tailrec`, the collections, `Ordering`, strings, companions,
abstract types, structural types, `null`, SAM conversion, Java interop,
imports, switches, `Using`, and static types made observable through
overload resolution (`static_types.scala`).

Several of the defects below were fixed independently on batch/w1 (libdecl,
libapply, rtverify, rtoutput, gbmisc); at the merge batch/w1's implementation

abstract-class SAMs, numeric widening in applicability, the numeric branch lub
(`numeric_branch_lub`, which the `try` join now uses as well), the companion
`apply`, and the `def adder` double pop. The rtprobe fixtures still pin all of
them.

## Fixed on agent/rtprobe

Each is pinned by `crates/cli/tests/rtprobe.rs` (fixtures `tests/fixtures/rtp_*`,
every expected file generated by scalac).

* Only the last guard of `x <- e if a; if b` filtered (parser kept one guard).
* A subclass overload with a narrower parameter (`B.f(String)` next to
  `A.f(Any)`, `E.equals(E)`) got an erasure bridge hijacking the parent
  method: `override_check::certainly_different` could not tell built-in
  types apart, so the pair was never proven an overload.
* A class overriding a generic trait member at a primitive type
  (`IntBox extends Box[Int] { override def put(t: Int) }`) got a mixin
  forwarder to the trait body instead of the bridge to its override.
* `==` always went through `BoxesRunTime.equals`, whose reference shortcut
  skips a user `equals`; nsc uses it only when both sides may be boxed numbers.
  Case class `equals` compared generic/`Any` fields with `Objects.equals`
  (`Gen(1, Nil) != Gen(1L, Nil)`).
* Numeric widening did not count toward overload applicability (`f(b: Byte)`
  picked `f(Any)` over `f(Int)`); the prelude's typed `println` stand-ins
  were removed with it, and arity pre-selection (`preSelectOverloaded`) gives
  `println(if (c) 1 else 2.0)` the expected type `Any`.
* `if`/`match`/`try` without an expected type joined numeric branches to
  `AnyVal` instead of the weak lub (`val y = if (c) 1 else 2.0` printed `1`).
* `-5.abs` parsed as `-(5.abs)`.
* `Int.box`/`Int.unbox` (and the other companions') called the library's `???`.
* `null.asInstanceOf[Int]` threw NullPointerException instead of giving `0`.
* The left operand of a right-associative operator ran after its receiver
  (`e(1) :: e(2) :: Nil` evaluated `e(2)` first); `restore_rassoc_order`.
* Parameter-accessor fields were stored after the super constructor call.
* `a.adder(1)` for `def adder: Int => Unit` popped twice (VerifyError).
* `5.signum` (a `RichInt` member inherited from `ScalaNumberProxy`) called a
  non-existent `$extension` on an unboxed receiver (VerifyError).
* A lambda parameter typed at a user value class reached an `$extension`
  call still boxed (VerifyError).
* SAM classes: primitive SAM parameters were read as objects (VerifyError);
  an abstract-class SAM was implemented as an interface
  (IncompatibleClassChangeError); a class SAM with constructor arguments was
  accepted.
* `case _: Array[_]` / `isInstanceOf[Array[_]]` tested `instanceof Object`.
* `var v: T = _` for an abstract `T` was rejected (17 scala-library errors).
* Unboxing `null` in erased generic code threw NullPointerException
  (`new Cell[Int].v + 1`); `emit_unbox` now uses `BoxesRunTime.unboxTo*`.
* A companion's hand-written `apply(d: Double)` suppressed the synthetic
  `apply(cents: Long)` the typer resolved to (NoSuchMethodError).
* An `object`'s early definitions ran after its traits' initializers.
* `Map(1 -> 2, 3 -> 4.5)` printed a `MapBuilderImpl`: a type variable bounded
  inside `Tuple2` was joined by the weak lub (`Double`), so `(1, 2)` looked
  inapplicable, and the call fell back to a view of the module
  (`BuildFrom.toBuildFrom(Map)`) whose one-parameter `apply` took the pairs
  tupled. The join is now the plain lub (and the lub of two value types is
  `AnyVal`), the factory's result reads every pair, and a receiver view whose
  member does not apply is undone before any argument adaptation --
  `Map(1 -> 2, "x")` is rejected again.
* `Vector(1, 2).updated(0, "s")`, `Vector(1) :+ "x"` and friends were typed
  at an element type one element did not have (ClassCastException), and a
  declared `[B >: A]` bound joined by the weak lub (`padTo(3, 1.5)` failed its
  own bound).
* Wrong acceptances now rejected: `new` of an abstract class or trait,
  extending a final class, case-to-case inheritance, a covariant type in a
  body `var`, `isInstanceOf[AnyVal]` / `case _: AnyVal`, a local
  `var x: Int = _`, a strict local val referring to itself, a `def x_=`
  next to a `var x`, and the subclass-overload tie nsc reports as ambiguous.
* A `def x_=` next to a `private[this] var x` is legal (the var has no
  setter), and `x = v` inside it stores the field; it was rejected as a double
  definition and, accepted, recursed into the hand-written setter forever.

## Not fixed

### A view of the `Map` module is found at all

The `Map(1 -> 2, "x")` fix above undoes the view when it does not help, but
the view should not have been a candidate: `BuildFrom.toBuildFrom` lives in
`BuildFrom`'s companion, which is not part of the implicit scope of
`Map.type` or of `?{def apply}`. nsc never finds it there. The implicit
scope used for receiver views is wider than nsc's.

### `SortedSet.map` narrowed without its `Ordering` (`static_types`)

```scala
val m = scala.collection.immutable.SortedSet(3, 1).map(_ * 2); println(m)
```

scalac: `TreeSet(2, 6)`. scala-rs: `ClassCastException: Set$Set2 cannot be cast
to SortedSet`. The call resolves to `IterableOps.map` (no `Ordering`), and
`check_apply::rebuild_from_receiver` then narrows its `Set[B]` to the
receiver's class. nsc picks `SortedSetOps.map[B](f)(implicit Ordering[B])`.
`needs_ordering_to_rebuild` guards `SortedMap`/`SortedSet` receivers only when
the call already carries the witness; this path does not reach it.

### `rebuild_from_receiver` for classes whose `CC`/`C` are not themselves (`coll_view_iterator`, `char_ops`)

```scala
println((1 to 5).view.map(_ * 2).filter(_ > 4).toList)   // CCE: View$Filter -> IndexedSeqView
println(('a' to 'c').map(_.toUpper))                     // CCE: Vector1 -> NumericRange
```

`IndexedSeqView[A]` is `IndexedSeqOps[A, View, View[A]]` and `NumericRange[T]`
is `IndexedSeqOps[T, IndexedSeq, NumericRange[T]]`: `filter` on the view and
`map` on the range return `View[A]` / `IndexedSeq[B]`, but the rebuild puts the
receiver's own class back. `maps_to_own_class` checks only that the element
type is the class's own parameter. The fix is to read the `CC` and `C`
arguments the class passes to `IterableOps` and rebuild a `C`-returning
member (`filter`, `take`, …) to `C` and a `CC[B]`-returning one (`map`, …) to
`CC`; `TreeSet` (`C = TreeSet[A]`, `CC = Set` for the Ordering-less `map`)
shows why the two must be separate.

### Name-based extractors (`match_extractors`)

```scala
final class NameOpt(val s: String) { def isEmpty = s.isEmpty; def get = s.reverse }
object Rev { def unapply(s: String): NameOpt = new NameOpt(s) }
"abc" match { case Rev(r) => println(r) }
```

scalac: `cba`. scala-rs: `VerifyError` -- the pattern code treats the
`unapply` result as a `scala.Option`. A `get` with `_1`/`_2` is rejected
(`gap_namebased_product`).

### Case class with a second parameter list (`case_class_methods`)

`case class Curried(a: Int)(val b: Int)`: scalac prints `Curried(1)` and
`Curried(1)(2) == Curried(1)(3)`; scala-rs prints `Curried(1,2)` and `false`.
Only the first list is the product (toString, equals, hashCode,
productArity); `namer` builds the synthetic members from all `ctor_fields`.

### `new Array[Unit](n)` (`unit_values`)

`new Array[Unit](2).toList`: scalac prints `List((), ())`; scala-rs
`List(null, null)`. Both allocate a `BoxedUnit[]` of nulls; scalac wraps it with
`Predef.wrapUnitArray` (an `ArraySeq.ofUnit`, whose elements are all `()`),
while `emit_array_wrap_to_iterable_ops` always calls `genericWrapArray`, which
sees an `Object[]` and builds an `ofRef`. The wrapper needs the static element
type, which that helper is not given.

### Tuple specialization (`tuples`)

`Tuple2(1, 2).getClass.getSimpleName` is `Tuple2$mcII$sp` under scalac and
`Tuple2` under scala-rs, which never selects the specialized subclass at a
construction site. Values and equality agree.

### Corpus neg tests unmasked

`neg/sabin2` "passed" at the baseline only because scala-rs rejected its
valid `var x: T = _`. With that accepted, its real error -- the path-dependent
mismatch in `a.set(b.get())` for `a, b: Base#Inner` -- was not reported: a
pre-existing wrong acceptance. Since the batch/w1 merge it is (`no matching
overload for (_1.T)Unit with arguments (Base.T)`), so the test passes for its
real reason. (`neg/t591`, unmasked the same way, is rejected for its real
reason by the `x_=` / `var x` clash check.)
