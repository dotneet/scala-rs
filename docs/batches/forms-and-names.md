The composed implementation addresses these connected families:

- Nested actual-base alignment for generic inference. A Named extends Value[String]
  argument inside (String, Value[A]) must constrain A from its Value base, not
  from Named's own empty argument list. Alignment recursively follows matching
  class/tuple shapes and function results. Function parameter types stay intact;
  original argument conformance still rejects invariant-container mismatches.
  Real scalatra-forms 3.2.1 inferred anonymous and named ValueType subclasses
  reproduce the gitbucket mapping failure and now execute like scalac in the
  first composed probe. Neither anonymous identity nor declaration order was
  the root. Repeated-variable constraint solving remains a separate harder root.
- Encoded symbol names in ScalaSignature. Raw TERMNAME/TYPENAME entries also
  carry string constants and internal storage suffixes, so their primitive
  writer is unchanged; symbol-bearing callers encode names explicitly. Storage
  encodes its source name before appending nsc's trailing-space suffix.
  Class/type references and owner chains use encoded names too.
- NameTransformer operator and Unicode handling. Backslash and $uXXXX escapes
  are supported in both directions, including paired UTF-16 surrogate escapes.
  Java identifier classification uses the complete JDK 17 / Unicode 13 BMP
  table, generated by a checked-in Java helper. A real released scala-library
  NameTransformer oracle compares every non-surrogate BMP character plus
  supplementary characters and encoded-name controls. Rust cannot represent
  isolated surrogates; malformed isolated surrogate escapes remain literal.
- Backquoted literal escapes. nsc scans these through getLitChars/getLitChar;
  its a\\b spelling denotes one backslash. The original diagnosis missed this
  lexical seam. The lexer now reads ordinary literal escapes and diagnoses
  empty identifiers and invalid escapes independently.
- Encoded type/member lookup and binary nesting. $plus is part of a name, not
  a nesting boundary; Outer$$plus$plus is nested while $plus$plus is top-level.
  Scala classpath names and completion paths distinguish those cases without
  changing Java class-name decoding. Pickled nested declarations, InnerClasses
  names and EnclosingMethod names preserve the same encoded identities.
